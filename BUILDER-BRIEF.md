You are working on a Windows desktop image editor (TypeScript engine + Tauri 2 shell, currently named **Pigment**, version 0.26.0). The product is being renamed to **Guazzo** before its first commercial release. This brief has two parts: (1) the rename, and (2) the compliance items a legal audit found must land before publishing. - Never hand-edit generated artifacts: `dist/`, `app-bundle.js`, `app-single.html`, `desktop-dist/`, `src-tauri/Cargo.lock`, `src-tauri/icons/*`. They are all regenerated by the build chain. Change sources, then rebuild.

- Keep code comments technically accurate: where a comment explains *why* something exists (e.g. the WebView2 data-dir rationale in `main.rs`), preserve the explanation and only update names.
- "Photoshop" in internal code comments is fine (comparative, not user-visible). "Photoshop-like" in the README is fine. Adobe marks must NOT appear in user-visible UI strings or the product name (section 6).
- Do the rename in one pass, then run the full build chain in section 1.8.
