# Guazzo 1.2.1

One fix, in the Move tool.

1.2.0 made a Move drag rewrite only the union of the layer's old and new
content, which took a 256 px layer on a 2048² canvas from 11.3 ms to 0.5 ms per
pointermove. To do that, the drag snapshot has to know where the content is, and
1.2.0 worked that out by walking every pixel of the layer on mousedown. On a
16384² document that is 268 million iterations before the first mouse move, and
it was slow enough to be felt as a stall when you grabbed the layer.

The bbox now comes from the layer's allocated tiles: a layer only allocates a
tile where something has been painted, so the answer is O(allocated tiles)
instead of O(pixels). The snapshot's dominant cost is the layer read itself,
which was already there.

- Before: mousedown on a 16384² layer scanned every pixel.
- After: 22 ms at 8192², 1.6 ms at 2048², for a layer occupying one tile.
- A bbox that is too large is only slower, never wrong, so an over-approximate
  bbox from tile allocation is safe by construction — and the pixel-exact
  reference test in `move.test.ts` still passes byte for byte.

## Verification

- `node scripts/ci.mjs`: 59 test files, 605 tests, 85 static pins, headless
  smoke, deterministic single-file build.
- Move output is byte-identical to 1.2.0 for the probe path (seven offsets,
  masked and unmasked) and to the naive full-canvas reference in the unit test.

## Installing

Same as 1.2.0: unzip and run `Guazzo.exe`. The exe is unsigned, so SmartScreen
will say "Unknown publisher" on first run; verify the download with
`SHA256SUMS.txt` or the `.zip.sha256` sidecar.
