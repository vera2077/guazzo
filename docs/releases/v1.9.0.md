# Guazzo 1.9.0

Per-run text sizes and colours. A text layer used to have one size and one colour
for the whole layer; now a selected run can be larger, smaller, or a different
colour, and the recipe keeps that per run.

## What changed

- **Select text, then set its size or colour.** The Size slider in the text options
  now applies to the selected run when there is one, and the new colour swatch next
  to it colours just that run. With nothing selected both act on the whole layer.
- **The size commits once, not once per pixel.** Dragging the slider updates the
  editor text live and wraps the run on release; wrapping on every input event
  would have produced hundreds of nested spans for one gesture.
- **The recipe is the source of truth.** Each run stores its own optional `size`
  and `color`; a run without an override uses the layer's base, so a document
  written before this release opens unchanged.
- **The rasteriser honours it.** Measurement, ascent and descent are per run, and
  the paint loop switches `fillStyle` mid-line, so one line can hold two colours.
  A shared helper (`src/engine/textruns.ts`) answers "what size and colour is this
  run?" for the rasteriser, the PSD writer and the editor, so those three cannot
  drift apart.
- **PSD carries it both ways.** Export writes each interval's `fontSize` and
  `fillColor`; import reads them back instead of admitting "text style runs
  collapsed". The old admission is gone, not hidden.
- **The project format validates it.** A file cannot inject a NaN size or a
  fractional colour channel that would reach `ctx.font` or produce an invalid
  `rgba()`.

## Verification

- Engine: 64 test files / 671 tests, including new tests for the shared run
  helpers, per-run fields in the project format, the PSD record shape, and a
  byte-level `writePsd` → `readPsd` round trip that returns `size 48` for the big
  run and `undefined` for the plain one.
- Smoke: the existing text and export paths still pass; the full gate
  (`node scripts/ci.mjs`) is green, including pins and the deterministic build.
- Not verified in this sandbox: the DOM text editor's selection handling with a
  real pointer. The headless smoke shim has no `Selection`/`Range`, so the
  authoring path is covered by reading and by the recipe tests, not by a click.

## Limits

- A run's size and colour are per run; there is no per-run font, tracking or
  baseline shift.
- PSD import still collapses runs that differ only in ways the model cannot hold
  (tracking, baseline, per-run font), and says so in the import report.
- Unsigned, no installer, no updater, as before.
