# Guazzo 1.4.0

Adjustment layers became editable, and the UI review found one way to lose the
window.

## Adjustment Settings

Until this release an adjustment layer could be *created* with a single
"Amount" slider that meant something different for every kind — Levels took it
as a gamma guess — and there was no way to open it again. This release replaces
that stub with a real editor:

- **Adjustment Settings…** on the Layer menu and the layer context menu reopens
  the selected adjustment layer with the controls its kind needs: levels,
  curves, exposure, vibrance, hue/saturation, colour balance (nine sliders plus
  preserve luminosity), black & white (six bands), photo filter (preset, density,
  preserve luminosity), brightness/contrast, posterize, threshold, and the two
  kinds with no settings (invert, desaturate) say so instead of showing a slider.
- Curves are drawn by hand on a 260 px editor — click to add, drag, double-click
  to remove, arrows to nudge — and the *same* widget is now used by the
  destructive Curves command, so the two surfaces cannot drift apart.
- Every edit is one undo step, and undo restores the **recipe**, not just the
  pixels: the non-destructive promise only holds if the numbers come back too.

## UI review fixes

- **Escape on "Unsaved changes" used to brick quitting.** Escape ran the close
  path without the cancel path, so the prompt never settled, the close request
  was never acknowledged, and the window could not be closed again for the rest
  of the session. Escape is now Cancel, and the prompt still comes back if you
  ask to quit again.
- Arrow keys in menus skip disabled rows; disabled rows carry a tooltip and the
  palette says *why* a command is unavailable instead of closing as if it ran.
- **Layer Mask ▸** (add, apply, delete), Rasterize Type and Quick Export are in
  the Layer menu, which also puts them in the command palette — the palette is
  built from the menus, so a context-menu-only command is unsearchable.
- The close prompt's destructive answer is no longer styled as the primary
  button, and a refusal is never the default.
- Failures now land in a persistent error slot that stays until dismissed,
  instead of a 2.6 s status hint that looked like success.
- The layer eye/lock/mask chips are real buttons with labels and a pressed
  state; the lock is visible without hovering.
- Enter in a dropdown or on a slider belongs to that control — it no longer
  fires the dialog's OK (Enter in Export's format list used to export).
- Menu labels and shortcuts agree across the menu bar and context menus
  ("New Layer" without a misleading ellipsis, `Ctrl+Shift+N` everywhere).

## Verified

- `61 test files / 637 tests` green, plus 85 pins and the UI smoke suite.
- The Escape bug is pinned twice: a smoke assertion that cancelling the close
  prompt still acknowledges the request, and a dialog unit test that Escape
  takes the cancel path.
- The Adjustment Settings round trip is asserted through the saved project
  JSON: create a Curves layer, bend it, save, reopen, bend again, undo back to
  the first recipe, redo to the second.

## Limitations

The executable is unsigned: Windows SmartScreen will warn on first run. Choose
"More info" → "Run anyway", or build it yourself from source. There is no
installer and no auto-updater; the app is not published to any store.
