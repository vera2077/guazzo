# Guazzo 1.3.0

Fill layers are now a real tool rather than a thing the importer could make.

## New

- **Multi-stop gradients.** The fill dialog started with two fixed swatches, which
  cannot express what a gradient is. Stops are a list now: add one *(+ Stop)*, remove
  it *(×)*, and set each position. Up to eight stops. The engine already interpolated
  between arbitrary stops; this is the surface that was missing.
- **Pattern fills.** Checkerboard, diagonal stripes and dots, generated from the
  pixel's cell — no image is vendored and nothing is downloaded, so a pattern stays
  sharp at any canvas size. The tile size is adjustable (2–256 px) and both colours
  are picked in the same dialog.
- **A live preview** in the fill dialog, painted with the compositor's own samplers.
  It cannot drift from what the layer will draw, because it is the same code.

## Fixed while building it

- A linear fill was half-blended at its trailing edge: the projection started at 0.5
  instead of 0. Found by the first test written for it, fixed by projecting the
  offset from the centre. Both directions are now pinned by tests.
- The bundler's collision guard caught two name clashes (`clamp01`, `KINDS`,
  `PATTERN_KINDS`) before they could ship as silent shadowing.
- Creating a fill layer from the Layer menu would have pushed the coupling metric
  over its baseline; the dialog lives in `src/ui/filldialog.ts` behind an explicit
  deps contract instead, so `main.ts` stayed at 84 coupled functions.

## Honest limitations

- A pattern or gradient fill has nowhere to live in a PSD fill record, so exporting a
  document containing one takes the documented single-composite fallback: the picture
  is preserved and the cause is named in the export admission. Solid fills still
  export as live records.
- The executable is unsigned, so Windows SmartScreen will warn on first run.
  There is no installer and no in-app updater.

## Verified

- Gate: 61 test files / 635 tests, pins, smoke, deterministic single-file build.
- The published zip is the one this release staged: `verify-asset` re-hashes it
  against `RELEASE.json`, and the artifact inside rebuilds byte-identically from a
  clean clone at this tag.
