# Guazzo 1.16.0

## What changed

**A Photoshop file now means what it says.** The import report used to admit
whole classes of adjustment and style; this release carries them.

- **Every adjustment field the model can express round-trips.** Per-channel
  Levels rows beside the composite, Exposure offset and gamma, Vibrance's
  saturation slider, Hue/Saturation colorize and its six per-range bands, and
  the black-and-white tint. Field-by-field admissions are gone; the report now
  stays silent for a file that only uses these.
- **Layer styles are live, not baked.** Shadow, inner shadow, outer and inner
  glow, bevel, solid colour, gradient overlay and stroke import as a recipe,
  render when the document composites, save in the project, and are written
  back on export as a style the recipient can still turn off. Before this, the
  pixels were painted once and the style was lost — which also meant an edit
  two minutes later left a stale shadow behind.
- **Gradient fills import live.** A linear or radial Photoshop gradient becomes
  a real fill layer with its stops and angle, so it can be re-edited instead of
  arriving as frozen pixels.
- **16- and 32-bit files are described honestly.** They open through the
  reader's 8-bit path, which truncates each sample to its high byte; the report
  now says so instead of claiming that values above 255 clip, which was never
  true.

## Verification

- `71 test files / 726 tests`; pins, smoke and the deterministic single-file
  build are green.
- New tests: `src/engine/tests/effects.test.ts` (style rendering, padding,
  normalisation, export units) and four round trips in
  `src/engine/tests/psdexport.test.ts` — per-channel Levels, Exposure
  offset/gamma, Vibrance saturation, Hue colorize and bands, B&W tint, layer
  styles, gradient fills. Each was mutation-probed: reverting the code makes the
  test fail.
- The import fixtures no longer expect an `effect` admission; the fixture named
  for effects now asserts the recipe arrives with its numbers.

## Limits

- Patterns and fills that carry a mask or styles still rasterise, and a placed
  file still arrives as pixels: the reader does not expose the placed file's
  original image, so a live re-edit cannot be reconstructed. Both are listed by
  name in `docs/COMPAT.md`.
- 16-bit precision is not the model: tiles are 8-bit RGBA. The file opens; the
  precision is the reader's.
- Layer comps, smart filters, video and 3D layers are still not read.
