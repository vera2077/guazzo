# Guazzo 1.14.0 — Smart objects

## What changed

A pixel layer can now keep its **original image** and render from it, instead of
being resampled in place.

- **Layer ▸ Convert to Smart Object** stores the layer's pixels as its source.
  Scaling that layer down and back up re-derives the picture from the source, so
  a round trip through 25 % returns within about two levels of the original,
  where two ordinary transforms leave a visibly softer image.
- **Free Transform** on a smart layer transforms the *source* once at the size
  you finish with, rather than compounding on already-resampled pixels.
- **Layer ▸ Replace Smart Object Contents…** swaps the source for a file you
  pick, rendered into the layer's current footprint — the transform you set is
  kept.
- **Layer ▸ Rasterize Smart Object** returns the layer to ordinary pixels.
- Duplicating a smart layer copies the layer, not the source image: duplicates
  share one immutable source, so a twenty-duplicate document does not hold
  twenty copies of it.
- The source travels in the project file (`.guazzo.json`, only when pixels are
  saved). A damaged source is reported and the layer keeps its rendered pixels
  rather than failing the load.

## Verification

`69 test files / 698 tests` green, plus the static pins, the headless UI smoke
and the deterministic single-file build, all in the usual gate.

The engine test that matters is comparative, not a smoke test: a 64 px
two-pixel-stripe image scaled to 25 % and back to 400 % must differ from the
original by at most two mean levels **and** be at least five levels closer than
the same two transforms applied to plain pixels. A "does not crash" assertion
would have passed for a feature that quietly resampled twice.

Mutation probes run for this release:

| Probe | Failure it produced |
| --- | --- |
| Conversion stores the source but never assigns it to the layer | `Rasterize Smart Object must be enabled once the layer is smart`, `an already-smart layer must not offer conversion again` |
| Rasterize leaves `layer.smart` in place | `after rasterizing, the layer can be made smart again` |
| Menu opened twice (toggle) in the smoke helper | `Layer menu must offer Rasterize Smart Object` |

## Limits, stated plainly

- **PSD export writes the rendered pixels.** Photoshop's own smart-object record
  is not produced, so a Guazzo smart layer arrives in Photoshop as a plain layer.
  The source lives in Guazzo's project format only.
- **One rotation samples once.** A 45° transform reads the source at an angle;
  rotating back re-samples the source again rather than recovering the axis-
  aligned bytes. Repeated arbitrary rotations still degrade, just far more slowly
  than resampling the visible pixels.
- **Painting is refused until you rasterize.** A stroke lands on rendered pixels
  that the next transform would discard, so the tools say "Rasterize the smart
  object before painting on it" instead of letting the paint disappear.
- Live text cannot be converted: it has no fixed pixels to keep. Rasterize the
  type first, then convert.

Nothing else changed: no file-format version bump for ordinary documents, and a
project without smart layers loads exactly as before.
