# Guazzo 1.17.4 - An installer that asks where to install

The setup program was a silent copy-and-hope: it wrote to one hard-coded folder,
and when Windows refused that folder it retried the same folder for ten seconds
and then printed a message the user could do nothing about. It now shows a
window, offers a folder, and never dead-ends.

## What changed

- **The installer is a window now.** Title, a one-line explanation, an editable
  install folder with **Change…**, a note line, a progress bar that moves while
  the payload is written, and an error page that scrolls instead of clipping.
- **Update / Reinstall are recognised.** If the chosen folder holds an older
  Guazzo (`version.txt`, falling back to `Guazzo.exe`), the subtitle says which
  version is there and the primary button reads **Update**. If it holds the same
  version, it reads **Reinstall** and says every file is replaced.
- **Existence is not writability.** The old probe returned true for any folder
  that existed, so a folder left by an earlier install passed the check and then
  `Guazzo.exe` failed with `Access is denied (os error 5)`. The probe now writes
  and removes a small file. A folder that cannot take that file is treated as
  unusable *before* anything is copied.
- **A refused folder is no longer a dead end.** The installer tries the chosen
  folder, then `%LOCALAPPDATA%\Guazzo`, `%APPDATA%\Guazzo`, `%USERPROFILE%\Guazzo`,
  `Documents\Guazzo`, and a folder beside the setup file; the first writable one
  is used and the completion page names the folder it actually used. Silent mode
  (`--silent`) goes through the same resolution.
- **Completion page.** A green tick, `Guazzo <version> is installed`, the real
  path, "To remove it later, use Settings ▸ Apps", and **Run Guazzo** / **Close**.
- **Two real defects found while building this**, both of which could ship:
  - `RegisterClassW` failed with `ERROR_INVALID_PARAMETER` because the window
    class passed the `IDC_ARROW` resource id (32512) where a cursor handle
    belongs; `LoadCursorW` now supplies the handle.
  - The window was created but never painted: `SetWindowTextW` on a child sends
    `EN_CHANGE` → `WM_COMMAND` → a handler that took the same non-reentrant
    mutex the caller already held. The UI state is now taken out of its slot
    while it is being edited, and nested calls no-op instead of deadlocking.

## Verification

- Screenshots of all three states: fresh install, update over `1.17.2`, reinstall
  over `1.17.3`, and the green completion page with **Run Guazzo**.
- A **denied** folder (`icacls /deny …(OI)(CI)(W)`) installs into the next
  writable fallback and names it on the completion page.
- Silent install and uninstall are exercised end-to-end by `scripts/build-setup.mjs`.
- Full gate green, pins, smoke, deterministic single-file build.

## Limits

The installer cannot grant itself write access to a folder Windows protects
(Controlled Folder Access, a folder-redirection tool, or a stale install held
open by another process). What it can do, and now does, is refuse before copying,
say which folder it used instead, and never present a success page after a
failure. Setup from a network share may still be blocked by policy.
