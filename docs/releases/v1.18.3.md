# Guazzo 1.18.3

A correctness release for selections and for the places where a control
promised something the code did not do.

## What could hurt you

- **A merged selection could edit the wrong pixels.** After Shift-add or
  Alt-subtract, the app kept the last drag rectangle beside the merged mask,
  and copy/cut/adjustments preferred the rectangle. Subtract a region until
  the selection was empty, then press Delete: the rectangle still described
  exactly the area you had just removed, unmasked. A merged selection now
  keeps only its mask.
- **A refusal could be announced on every pointer move.** The layer panel
  cleared its own "illegal drop" marker before testing it, so dragging a
  layer into a forbidden place rewrote the live region continuously and the
  message never expired. It now announces once per dragged row.
- **Autosave could be switched off by opening a file.** The crash-recovery
  bar hid itself whenever a document was replaced, and autosave is suspended
  while that bar is up — so opening anything after a crash left every later
  edit unwritten. The bar now stays until Restore or Discard.
- **The installer could overwrite a file on request.** `--extract-payload`
  wrote the fixed payload over any writable path; it now refuses an existing
  file. Folders under a junction above a missing component are judged by
  where the resolved path points, not by the string that names it.
- **A malformed release manifest could skip the payload checks.** The legacy
  escape hatch accepted a manifest that declared the wrong installer
  sources; a present-but-wrong list is now refused.

## What was wrong on screen

- Undo at history position 0 (the first Ctrl+Z of a session) stranded focus
  on the page body; it now lands on the first step.
- Duplicate, New Layer and Merge Down rebuilt the rows and dropped the
  focused row; the panel restores it.
- The Shape tool's Stroke swatch stayed dimmed and disabled after the width
  slider left zero, and stayed enabled when it returned to zero.
- Every options-bar number field lost its name when the tooltip system
  moved `title` to `data-tip`, so screen readers announced an unnamed spin
  button.
- Shift at press meant both "add to selection" and "constrain to square",
  so Shift could never add a rectangle; holding Shift after the press now
  constrains, pressing it before adds.

## Verification

- `npm test` equivalent: 79 test files / 806 tests, 107 static invariants,
  headless UI smoke, deterministic single-file build.
- New pins: merged selections drop their rect/geometry, Shift-at-press is
  the modifier, a refused drop speaks once, history focus falls back, the
  stroke swatch tracks width, number fields are named.
- Installer rebuilt and its GUI re-checked by screenshot; `--extract-payload`
  refuses an existing target.
