# Guazzo 1.18.6

The recovery screen stops inventing work that was never lost, and three ways a
crash copy could disappear are closed.

## What was wrong

- **A saved session was offered as "recovered" work.** Every launch found the
  autosave file left by the previous session — even one you saved and closed —
  and asked you to restore it. Dismissing it wrote the file again, so the
  question came back on the next launch. There was no clean-exit marker.
- **A third crash session could be parked forever.** The recovery screen kept
  the two newest snapshots and moved an older one into an archive slot that was
  never read, then deleted it with the rest when you chose Restore or Discard.
  The bar said "also kept until you choose"; it was not.
- **A partial restore deleted what failed to load.** If one document in a
  multi-document snapshot could not be rebuilt, the others were restored, the
  "drop the slots after writing" flag was set, and the next autosave removed the
  only copy of the document that had failed.
- **Tab walked out of the recovery question.** The bar took focus, but the next
  Tab hid the whole panel column behind it, so a keyboard user could not reach
  Discard without losing the window's chrome.
- **A rotated smart object corrupted itself on the next transform.** A rotation
  is not stored on the layer, so the second transform derived its scale from the
  rotated bounding box (32 px became 46, then 66) and re-rendered the source at
  the wrong size.
- **Export As claimed every PSD record survives a smart object.** A smart object
  is written as pixels, and its note was hidden because the export dialog only
  counted layers that need flattening, not the notes beside them.

## What changed

- A v2 autosave snapshot records whether its session had anything unsaved. A
  snapshot written by a session where every document was saved is dropped at
  boot instead of being offered; the bar no longer appears for work you kept.
- The archive slot joins the boot sort. A third distinct crash session is now
  offered (the bar names the older one) instead of being parked forever.
- Restore only drops the crash slots when **every** entry came back. A partial
  restore keeps them and says which document failed.
- The recovery bar owns its Tab trap: Tab and Shift+Tab move between Restore
  and Discard and never into the panels behind the question.
- A smart object that is rotated is rasterised for that transform, with a status
  line that says so; undo puts the source back. Edge-clipped smart objects
  already behaved this way.
- Export As shows the smart-object note and drops the "all records survive"
  sentence when a note exists.
- `verify-asset` refuses a manifest that does not name `installerSha256` or the
  Setup, so a release cannot publish an installer it never attested.

## Verification

- `node scripts/ci.mjs` — 79 test files / 810 tests, 113 pins, smoke, and the
  deterministic single-file build.
- New test: a snapshot records whether its session had anything unsaved, and an
  ordinary (dirty) snapshot does not claim to be clean.
- Smoke: boot copies the offered snapshot into its own slot before the live file
  is written; Restore keeps that slot until the restored tabs are on disk;
  after the write the crash slots are gone; Tab and Shift+Tab stay on the bar's
  two answers.
- The packed payload is still proven against the Setup that ships
  (`Setup embeds payload …`, `payload.bin matches 6 release files`).

## What this does not fix

Photoshop features that need a model Guazzo does not have are still listed as
deferred in `docs/PHOTOSHOP-COVERAGE.md` (Object Selection, Make Work Path, path
editing, History/Art History brush, Content-Aware Move, vertical type, and the
Channels/Paths/Actions panels). The Windows build is unsigned.
