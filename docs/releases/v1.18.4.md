# Guazzo 1.18.4

A correctness release for two ways a session could be lost, and for the
keyboard model around panels and the recovery bar.

## What could hurt you

- **A 16-bit PSD imported as fully opaque, and a 32-bit PSD imported black
  and transparent.** The importer shifted 16-bit colour samples but clamped
  the alpha sample to 1.0 before scaling, so any layer with partial
  transparency became opaque; and it divided the 0..1 float samples of a
  32-bit document by 65535, so all four channels rounded to zero. Alpha is
  now scaled per depth (0..1, 0..65535, 0..255) and 32-bit colour floats are
  read in their own unit. Saving made either loss permanent.
- **A second crash could hide the newer session.** After a crash the
  recovery bar was up and autosave wrote the live slot; a crash during that
  window left two snapshots, and boot read the older recovery slot first
  and returned. The newer work was never offered and the next autosave
  overwrote it. Both slots are read now and the newer snapshot is offered.
- **Boot deleted one of the two snapshots before you saw it.** Parking the
  offered snapshot in the recovery slot and removing the live one meant that
  a crash during the bar hid the older session, and quitting without
  choosing dropped it — the loss Discard guards with a confirm. Nothing is
  written or deleted at boot now; the bar names the older snapshot when two
  exist, and only Restore or Discard clears the slots.
- **1.18.3 said opening a file no longer switched autosave off — it did.**
  The fix removed the bar from `replaceDocument` but `writeAutosave` still
  returned while the bar was up, so nothing painted after that open was
  written. The crashed session now lives in its own recovery slot and the
  live session keeps autosaving; Restore and Discard delete the slot and
  ask for a write. This release makes the 1.18.3 claim true.
- **The uninstaller did not respect the installer's scope rule.** It
  deleted the payload names from whatever folder it was handed. It now
  resolves and validates the path first, and the installer re-checks the
  resolved path after creating the folder.
- **A legacy release manifest could skip the installer checks.** The
  `GUAZZO_ACCEPT_LEGACY_MANIFEST` opt-out let a manual run green-light a
  manifest that proved nothing about the Setup. There is no opt-out now.

## What was wrong on screen

- Pressing Enter or Space on a focused panel header also reached the window
  shortcut layer, so folding a panel with Enter committed a half-drawn pen
  path or applied a crop, and Space armed pan.
- Restore and Discard removed the bar and its focused button without moving
  focus, leaving it on `<body>`; the next Tab then hid the panel column.
- Undoing a layer add (or redoing a delete) while that row was focused
  stranded focus for the same reason.
- History scrolled the current step into view on undo but not on redo, so a
  redo while the list was scrolled up left the list looking frozen.
- Merge Down removed the focused row and dropped focus; it now lands on the
  layer it merged into.
- Layer rows had no concise accessible name and the rename field was
  unnamed; both are named now.

## Verification

- `79 test files / 807 tests`, `111` static pins, the UI smoke, and the
  deterministic single-file build pass.
- New tests: a 16-bit layer with alpha 65535 / 32768 / 328 imports as
  255 / 128 / 1 (the old test used only 65535, which is why the clamp
  survived it); a 32-bit layer of `[0,0,0,0.5]` and `[1,1,1,1]` imports as
  `0,0,0,128` and `255,255,255,255`; an 800 px source at x=50 in a 200 px
  footprint no longer collapses to 138 px on an identity transform.
- Probes: removing the recovery-slot delete fails the Restore assertion;
  removing the depth normalisation fails the 16-bit alpha test.
