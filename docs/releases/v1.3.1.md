# Guazzo 1.3.1

A UI-correctness release. Nothing new to learn: the fill layers from 1.3.0 are
the same, they just stop fighting the keyboard, the screen reader and the
900-pixel window.

## Fixed

- **Tab no longer dead-ends in a dialog.** The tab ring included controls the
  dialog was hiding with `display: none`, where `focus()` does nothing — so
  forward Tab stalled and OK/Cancel could not be reached from the keyboard.
  Hidden controls are now skipped when the ring is built.
- **Closing a menu-opened dialog returns focus to the menu bar**, not to
  `<body>`. The opener used to be the menu row itself, which is removed from
  the DOM as the dialog opens.
- **The command palette names what it can do.** Commands the menus grey out
  (Merge Down on a single layer, for instance) now appear greyed in the palette
  too, marked `aria-disabled`, and Enter on them does nothing instead of
  half-running. The input is the combobox that owns the list, so the active row
  is announced from the element the user is actually focused on.
- **Options-bar controls have names and states.** The Shape, Sample Size,
  Retouch Mode, Tonal Range, Sponge Mode, Marquee Shape, Gradient Shape and Font
  selects carry `aria-label`; B/I/U/S carry `aria-pressed`.
- **The layer-row focus ring is visible.** It used a 1.97:1 token the app's own
  contrast rule rejects; it is now the solid accent at 2 px.
- **Fill thumbnails show the fill.** A gradient thumbnail draws the gradient and
  a pattern thumbnail draws its cells, instead of both painting the first
  colour.
- **The options pager keeps its first page at 900 px.** Its width is reserved
  before the buttons are placed, so page one is no longer clipped.

## Under the hood

- `scripts/ui-smoke.mjs`'s DOM shim now models layout boxes: `getClientRects()`
  returns nothing for a subtree with `display: none`, which is what makes the
  tab-ring regression observable. Three new assertions fail if the ring includes
  a hidden control, if the fill dialog stops painting its preview, or if the
  palette input stops being the combobox.

## Verified

- `node scripts/ci.mjs` green: 61 test files, 635 tests, pins, smoke, and a
  byte-identical single-file build.
- Each fix was mutation-probed: reverted, the gate fails with the named
  assertion; restored, it passes.
- Windows exe, unsigned, no installer, no updater. SmartScreen will warn on the
  first run; the integrity level is Medium and `WebView2Loader.dll` is required
  beside the exe.
