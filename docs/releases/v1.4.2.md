# Guazzo 1.4.2

The unsaved-changes prompt can save.

## What changed

- **A third answer on the close prompt.** It used to offer "close without
  saving" or nothing. It now offers **Save**: every document with unsaved work
  is written first — switching tabs as needed, which also commits a live
  transform or text edit — and the window closes only once nothing is dirty.
- **A cancelled save is a "no".** If the native save dialog is dismissed, the
  window stays open and the document keeps its dirty mark. The prompt closes;
  the work is still there.
- The destructive answer is still neutral, and the Escape fix from 1.4.0 is
  unchanged: every exit from the prompt acks the OS request, so the window can
  always be closed.

## Verified

- `61 test files / 637 tests` green, 85 pins, smoke, deterministic artifact.
- Smoke drives the whole loop for real: close request → Save → native write
  invoked → dirty cleared → force-close; and close request → Save → dialog
  cancelled → no close, still dirty. Mutation probe (`if (false && saveFirst)`)
  fails all four assertions.
- The extra button resolves the dialog through the same cancel path as Escape,
  so `ask()` still settles — the 1.4.0 unquittable-window bug cannot return
  through this door.

## Limitations

Unsigned executable (SmartScreen will warn), no installer, no auto-updater.
