# Guazzo 1.18.9

The other half of the mask-undo fix, plus two recovery and installer corrections.

## Select and Mask can be undone

1.18.8 taught Add Layer Mask to detach a mask it created when you press Ctrl+Z.
Select and Mask creates one the same way and was left out: undoing it restored
the mask's pixels and left the mask attached, so the layer kept an empty,
fully-revealing mask, the next Add Layer Mask merged into it, and Apply/Delete
acted on a mask you had undone.

Both entries now record whether the mask existed and reverse that too.

## Clear Mask and Fill Mask can be redone

Both captured the mask's tiles and then handed that same capture to the history
command as the *before* image. The command photographs the *after* image when it
is created, so both images were identical: undo looked right by luck, redo
restored the mask you had just cleared or filled, and Clear on an empty mask
recorded no entry at all — the next Ctrl+Z skipped past it while the mask stayed
cleared. Both now capture, mutate, then record.

## Recovery keeps a fourth crash session

When four distinct crash sessions exist, the archive slot already holds one the
bar cannot name. Parking the second-newest over the parked slot destroyed that
session while logging that it had been kept. The parked session is now left
alone, and the warning says so.

## Installer

The fallback path probes and installs into the canonical folder that
`dir_allowed` validated, not the raw text from the folder box, and the Done page
names the folder that was actually used.

## Performance

- Comparing snapshots for deletion reads the slot's bytes directly instead of
  decoding up to 4096 tiles and a whole document per slot.
- The Move-tool tile release runs once when the drag is committed, not on every
  pointermove; undo releases only the tiles that undo itself emptied.
