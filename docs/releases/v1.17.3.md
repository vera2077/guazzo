# Guazzo 1.17.3

A setup fix. The editor is unchanged.

## What was wrong

Setup could stop with

> Guazzo could not be installed
> could not create C:\Users\…\AppData\Local\Programs\Guazzo: Access is denied. (os error 5)

The folder is the default install location, and the message is Windows' report
for a directory that cannot be created *right now*. In practice that is almost
never a permissions problem: Windows returns the same error for a folder that
was deleted by the uninstaller seconds ago and is still finishing its removal,
for a folder an antivirus scanner is still holding, and for a folder left by an
earlier install whose files are read-only or locked.

Setup used to try once, fail immediately, and — worse — exit with code 0, so a
silent failure looked like success to anything scripting it.

## What changed

- Setup now retries creating the folder for up to **ten seconds** (20 attempts,
  500 ms apart) before deciding it cannot.
- If the folder exists and holds nothing but Guazzo's own files, Setup removes
  that stale folder and creates it again.
- The failure message now says what Windows means by it, names the folder, and
  offers a second location (`--dir "%LOCALAPPDATA%\Programs\Guazzo2"`).
- A copy of the message is written to `guazzo-setup.log` beside the setup file
  (falling back to the temp folder), and the message says where.
- A failed install now exits **1**, so the release test can see it. It could not
  before: there was no exit call at all, and the installer test's status checks
  were therefore unable to fail.

## If you hit this

1. Close Guazzo if it is running.
2. Try the setup again — the ten-second retry covers the common case.
3. If it still refuses, delete `%LOCALAPPDATA%\Programs\Guazzo` and run Setup.
4. Or install elsewhere:
   `Guazzo-v1.17.3-Setup.exe --dir "%LOCALAPPDATA%\Programs\Guazzo2"`

Nothing is left half-installed: Setup writes the payload only after the folder
is ready.

## Verification

- `scripts/build-setup.mjs` — install, assert all six files and `uninstall.exe`,
  uninstall, assert the folder is gone. Green.
- Denied-parent test: `icacls .setup-parent /deny melodi:(OI)(CI)(W)`, then Setup
  with `--dir .setup-parent/Guazzo` → ten seconds of retries, exit **1**, message
  names the folder and the log, `guazzo-setup.log` written with the version and
  target.
- Upgrade test: Setup run twice over the same install → exit 0 both times.
- Locked-executable test: `Guazzo.exe` held open with `FileShare.None` → exit 1,
  message names the file and says to close Guazzo.
- Gate: 72 test files / 735 tests, pins, smoke, deterministic single-file build.

## Limits

The retry and the repair cover the states above; they cannot make a folder that
is genuinely read-only writable. That case is now named rather than reported as
a bare `os error 5`.
