# Guazzo 1.18.0

The release that fills in the toolbox. Nine tools and two panels arrived since
1.17.4, each with an engine test and a headless UI assertion, and the review
rounds that followed turned up more than the tools themselves.

## New tools

- **Colour Sampler (Shift+I)** — up to four readouts pinned to the canvas, each
  showing its position and hex value; Alt-click or Clear Samples empties them.
- **Ruler (Shift+R)** — drag a measurement; the bar reports W, H, distance and
  the angle measured counter-clockwise from the horizontal, the way Photoshop
  reports it. Esc clears it. The ruler is read-only: it never touches pixels.
- **Background Eraser (Shift+E)** — samples the colour under the first dab and
  erases that colour as the stroke moves, with tolerance and hardness. The
  sample is taken per stroke, not continuously.
- **Pattern Stamp (Shift+P)** — paints a checker, stripe or dot pattern with a
  tile scale, through the same dab engine as the brush.
- **Mixer Brush (Shift+K)** — the stroke picks up the colour already on the
  layer and mixes toward the foreground by the Wet amount.
- **Colour Replacement (Shift+Y)** — repaints a sampled colour within a
  tolerance while keeping each pixel's luminosity. A true HSL swap would treat
  saturated ramps differently; the bar says so instead of hiding it.
- **Count (Shift+C)** — numbered view-only markers; Clear Counts removes them.
  They are not saved with the document.
- **Patch (Shift+J)** — drag a selection onto the pixels that should replace
  it; the result is one undoable step.
- **Note (Shift+N)** — numbered markers with text, hover reads them back. Like
  Count, they belong to the view, not the picture.
- **Magnetic Lasso (Shift+L)** — the third lasso: the freehand lasso, the
  polygonal lasso and the magnetic edge follower now share one key, and L
  cycles them. The follower samples edges on release rather than snapping
  continuously, which keeps the drag responsive on large documents.
- **Freeform Pen** — the Pen bar's freehand mode: drag a path; on release it
  closes into a selection.

## New panels

- **Histogram** — R, G, B with a luma outline, mean, and clipped shadow and
  highlight shares. It refreshes when the composite changes and not on every
  pointer move, so painting stays smooth.
- **Info** — position, composite colour, selection extent and canvas size under
  the pointer.

## Colour Range

Select ▸ Colour Range now exists: pick a fuzziness, and the mask selects every
pixel near the foreground colour. It was the one Select entry the menu was
missing.

## What was wrong under the tools

- **The mask chip is a surface, not a hint.** Delete, Edit ▸ Fill, the bucket,
  the gradient and Smart Fill wrote layer pixels while the mask chip was lit.
  Clear and Fill now write the mask ("Clear Mask" / "Fill Mask" in History); the
  tools that can only fill pixels say so instead of refusing with advice to
  "paint the mask" they cannot follow.
- **A lock means a lock.** Free Transform still moved locked layers, and Apply
  Layer Mask still baked one. Both ask the same guard as the brush now.
- **A pass-through group honours every control the panel offers.** Opacity,
  blend mode and mask promoted it to isolated; clipping was silently ignored,
  so a clipped pass-through group looked applied and painted nothing.
- **Free Transform of a locked layer, Apply Layer Mask on a computed layer,**
  and Alt-drag with a shape on either used to be refused *after* the damage or
  before the harmless branch — the shape ghost stayed on screen when the guard
  fired on a selection that writes no pixels.
- **Adjustments palette** is clamped when it opens and when the window resizes,
  and opening it focuses the first control rather than its close button.
- **Legacy installers upgrade again.** Builds before 1.17.4 wrote no
  `version.txt`; the installer offered "Update" for exactly those folders and
  then refused them as foreign. It now recognises an exe + page pair as a
  legacy install, and still validates the version file when one exists.
- **TIFF** refuses strips that do not cover every row instead of importing
  zero-filled bands, and budgets the row buffer as well as the RGBA output.
- **The dev server** sends `nosniff`.

## Not in this release, on purpose

`docs/PHOTOSHOP-COVERAGE.md` lists every row that is still ✖ with the model it
would need: Object Selection and Make Work Path need a resolution-independent
selection/path model; anchor-point editing and Path Selection need a path
editor; History/Art History brushes need a paint-from-history path; vertical
type needs a second text layout; Channels, Paths and Actions need panels with
state the app does not keep. A row moves to ✔ only when a test or the smoke run
proves the behaviour — not when a menu entry exists.

## Verification

- Gate: 79 test files / 793 tests, pins, smoke, deterministic single-file
  build.
- Every claim above was mutation-probed: the lock/transform assertion is red
  with both guards removed; the mask-surface paths are covered by engine tests
  for Clear/Fill and by the guard's unit cases.
