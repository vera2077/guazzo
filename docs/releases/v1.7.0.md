# Guazzo 1.7.0

**Selective Colour is a live adjustment kind.** This is the control Photoshop
builders reach for when one part of a picture is the wrong colour and the rest is
fine: pick a range, move four inks, and only the pixels in that range move.

## What it does

- **Nine ranges** — six by hue (reds, yellows, greens, cyans, blues, magentas)
  and three by tone (whites, neutrals, blacks).
- **Four offsets per range** — cyan, magenta, yellow, black, in percent from
  −100 to +100.
- **Relative or absolute** — relative moves a share of the ink already on the
  page, absolute adds a flat percentage of the full channel. Photoshop's default
  is relative, so that is the default here.
- **One set of sliders** — switching ranges keeps every other range's numbers,
  and the dialog never loses an edit made to the range you just left.
- **Live and undoable** — the layer is a recipe, not a bake: it reopens in
  **Adjustment Settings…**, takes masks and blend modes, and one undo restores
  the previous recipe.

## Fidelity, stated plainly

The recipe round-trips through PSD as a real `selective color` record, with the
percent values and the mode intact, so reopening the file in Guazzo gives the
same render and Photoshop reads the same numbers. Photoshop's own colour space
and range falloffs differ from this implementation's, so the *appearance* there
can differ slightly even though the values are exact. That is the same caveat as
exposure, and it is why the record is written rather than the pixels.

A file with damaged offsets falls back to identity rather than applying half a
range: an unreadable recipe should look unchanged, not subtly wrong.

## Verification

- `node scripts/ci.mjs` → 61 test files, 650 tests, pins, smoke, deterministic
  artifact.
- Engine tests: hue weight ownership (a saturated red belongs to Reds, not its
  neighbours), evenly split weights between adjacent hues, greys in the tone
  ranges, absolute vs relative ink maths, identity short-circuit, and the
  sanitiser's clamping.
- PSD test: record shape, `ag.writePsd` → `ag.readPsd` → import returns the same
  ranges and mode.
- Smoke: the dialog exposes one set of four sliders, keeps Reds' numbers while
  Blues is edited, stores only the ranges that were touched, and the saved
  project carries them. Probe: removing the save-on-switch makes three of those
  assertions fail.
